# Переработка вычислений и перенос на GPU

Дополняет `REIMPLEMENTATION.md`. Там описана текущая система, здесь — диагноз и то, какой ей быть.

---

## 1. Диагноз: насколько запутаны текущие вычисления

Коротко: вычисления — **каскад отдельно подогнанных этапов**. У каждого этапа своя модель, свои параметры и свои
пороги. Глобальный поиск собран вручную из генераторов кандидатов и сеток. Решения «да/нет» принимаются порогами,
подобранными на 8 объектах. Почти каждое исправление последних недель — ещё один этап или ещё одно правило поверх
прежних, а не устранение причины.

### 1.1 Одна физика — четыре несовместимые модели
| Где | Модель | Чего в ней нет |
|---|---|---|
| поза (`pose_pix`) | без освещения, сдвиги опор полос (σ 25 м) | освещения, вращения |
| вращение (`solve_spin`) | без освещения, **без сдвигов опор** (берёт опоры, переписанные в `.pkl` прошлым этапом) | освещения |
| направление | с освещением, дожим найденного решения и двойников | — (но только как довесок) |
| центр масс / кувыркание | отдельные классы `DiffSpinCoM`, `DiffTumble`, свои раскладки `x` (`x[-3:]`, `x[-6:-3]`, `x[-11:-8]`…) | освещения, сдвигов опор |

Следствие: скорость получают моделью, которая объект описывает заведомо неверно (без света). Отсюда смещение,
например 32851 с освещённой подстановкой даёт 67,8 вместо 60 °/с. Потом знак направления выбирают другой моделью.
Центр масс считают третьей при закреплённом вращении — отсюда заниженная σ на 30245.

### 1.2 Состояние, которое этапы переписывают друг другу
- `pose_write.py` переписывает опоры полос в `results/shape/*.pkl` — следующий этап видит уже другие данные.
  Порядок запуска меняет результат.
- Варианты задаются суффиксами имён файлов (`_nongrey_shade_mm_tmismatch_v2`) и переменными окружения
  (15 штук: `S2_COARSE_NG`, `S2_MASK_SIZE`, `PREP_UNTIL`, `SPIN_TAG`…). Конфигурации прогона нигде нет.
- Подстановки (проверка подстановкой) по-своему реализованы в `spin_real.py`, `com_test.py`, `tumble_test.py`,
  `spin_pix_test.py`.

### 1.3 Глобальный поиск собран вручную (`solve_spin`, ~40 ручных констант)
1. Позы подгрупп по 0,2 с.
2. Позы групп по 1 с.
3. Кандидаты ω из пар минимумов и целых k.
4. Перебор ω (120 осей × 100 скоростей) при 8 позах «самой информативной» группы.
5. Грубая подгонка 120 итераций, затем точная 60 итераций, затем дожим 4 лучших.
6. Профиль оси: 200 направлений × 15 величин × 14 баз.
7. Перебор 600 поз × 120 осей при 5 кратных скоростях.
8. Зеркальные двойники.

Каждый шаг добавлен после найденного провала и чинит один класс ошибок. Полнота поиска не гарантирована: скорость
выше 200 °/с не перебирается, но подгонка туда уходит — так получались 399 и 1032 °/с.

### 1.4 Решения — пороги, а не вероятности
- Вращение: BIC κ·3·ln N, затем отложенные моменты (> 2κ·K и ≥ 2/3 информативных), затем «≥ 3 моментов».
- Направление: двойник хуже на > 2κ·3.
- Обнаружение: медиана + 4, второй ярус Гумбеля 8,93·10⁻⁴, окно ±3σ по формуле, подогнанной на 17 пролётах.

Каждое правило подобрано и проверено на 3–8 объектах. Калибровки на тысячах подстановок нет. Вероятности
ошибок первого и второго рода неизвестны.

### 1.5 Погрешности — по локальной кривизне
- σ по гессиану: в части случаев не положительно определён — у плоских направлений приводов `inf`.
- σ при закреплённых остальных параметрах: занижена в 2–3 раза.
- σ по профилю: лучше, но на одной геометрии всё равно занижена в 2 раза.
- Многомодальность (двойники, кратные скорости, симметрии тела) в σ не входит: она обрабатывается отдельными
  правилами.

### 1.6 Численные мелочи, которые съели время
- float32 в сумме невязки (шум ~0,01–0,1 при L ≈ 8000) ломает разностные производные: нужны шаги «выше шума».
- Точные НК перебором 2^k активных множеств внутри функции потерь — неудобно, недифференцируемый выбор.
- 4 потока torch на занятых ядрах — замедление ×10–100.
- Подгонка CV заново на каждом отложенном моменте: ×(K+1) к времени, потому что на CPU нет пакетов.

### 1.7 Что в текущих вычислениях правильно и переносится как есть
- Геометрия push-broom: моменты полос, 3D-углы, GPS Sentinel, якобиан J.
- Дифференцируемая модель «пятен»: проекция площади, ядро, точечное размещение.
- Модель заслонения фона.
- Точные НК яркостей по полосам; яркости по полосам, а не серые.
- Идея проверки отложенными моментами съёмки.
- Иерархия движений: статика ⊂ вращение ⊂ кувыркание, плюс центр масс как центр вращения.
- Подстановки «как настоящий объект».
- Регрессия по эталонам.

## 2. Причина в одном предложении

Нет **одной генеративной модели наблюдения** со всеми мешающими параметрами и **одного вывода** по ней. На CPU
полный вывод был не по карману, и его заменяли каскадом дешёвых этапов с ручными правилами. GPU снимает именно
это ограничение.

## 3. Целевая архитектура: модель, вывод, калибровка

```
Observation (неизменяемый)  ──►  ForwardModel (GPU, пакет гипотез)  ──►  Likelihood (НК яркостей, шум)
                                         ▲                                    │
                                         │                                    ▼
                                 Inference: глобальный перебор → локальный Гаусс–Ньютон/LM →
                                            апостериорное (многомодальный Лаплас + HMC) → сравнение моделей
                                                                              │
                                                                              ▼
                                         Result (версия кода + конфиг + апостериорные сводки)
Calibration: тысячи подстановок, нарисованных НЕЗАВИСИМЫМ рендером → пороги и покрытие интервалов
```

### 3.1 Данные
- **`Observation`** — одна запись на пролёт: окна остатков по полосам (родное разрешение), фон, σ шума, моменты
  полос, якобианы, направления на Солнце и Sentinel, орбита-априори с ковариацией.
  Создаётся один раз и больше не меняется. Никаких `.pkl`, переписываемых следующими этапами.
- **`Result`** — версия кода (хеш), конфиг, апостериорные сводки, ссылки на `Observation`.
- **Конфиг** — один типизированный файл (dataclass/yaml). Вместо переменных окружения и суффиксов — поле конфига.

### 3.2 Прямая модель — одна на всё
Параметры гипотезы θ:

| Блок | Параметры | Априори |
|---|---|---|
| орбита | поправка вдоль, поперёк, радиус (м); **сдвиг опоры каждой полосы** (2 на полосу) | ковариация источника орбиты (§17 THEORY); σ опор 25 м |
| форма | модель каталога: приводы крыльев. Без модели: примитивы (цилиндр, пластина, бокс) или воксели с регуляризацией | по типу объекта |
| движение | R₀ (кватернион), ω₀, центр масс c (3), главные оси q (3), ln I₁/I₃, ln I₂/I₃ | статика ⊂ вращение (q, λ выключены) ⊂ кувыркание |
| свет | двусторонние материалы (лицевая/тыльная сторона), Ламберт + блик (показатель — параметр), свет Земли | физические диапазоны |
| яркости | ρ материала × полоса — **линейные, исключаются точно** (НК) | ≥ 0 |
| шум | σ полосы × κ, робастная функция потерь | κ из пустых окон |

Поворот R(t) — интегрирование уравнений Эйлера: РК4 по ω, экспонента на шаге — одна формула для всех движений.
Положение точки: p(t) = орбита(t) + R(t)(q − c).

**Освещение включено всегда.** Отдельной модели «без света» нет: направление, скорость и центр масс оцениваются
одной моделью совместно.

### 3.3 Вывод — один движок вместо каскада
1. **Глобальный перебор на GPU** по грубой модели (пятна ≤ 3 м). Декартово произведение: R₀ (SO(3), ~5·10³) ×
   ось ω (~500) × |ω| (0–400 °/с, шаг из разрешения пролёта) × двойники. Это ~10⁸–10⁹ гипотез; на одной GPU —
   минуты на объект. Генераторы кандидатов из пар минимумов, «информативная группа» и целые k больше не нужны:
   всё есть в переборе.
2. **Локально**: пакетный Левенберг–Марквардт по точной модели для top-K (K ~ 10³) — все параметры совместно
   (орбита, опоры, движение, центр масс, свет).
3. **Апостериорное**: моды объединяются по похожести. Лаплас на каждой моде, веса мод — по доказательству
   модели. Итоговые интервалы — HMC/NUTS по точной модели (пакетно, цепи параллельно). Двойники, кратные скорости
   и симметрии тела входят в апостериорное как моды, а не как отдельные правила.
4. **Сравнение моделей движения** (статика / вращение / кувыркание; с центром масс или без) — по доказательству
   (Лаплас + поправка за моды). Плюс **отложенные моменты съёмки** как проверка: на GPU все K отложенных
   выполняются одним пакетом.
5. **Определимость** берётся из апостериорного, а не из правила «≥ 3 моментов». Если апостериорное по ω
   многомодально или широкое, ответ — «не определяется», с интервалом.

**Выход**:
- P(вращается), интервал |ω|, ось с вероятностью направления (а не «определено/нет»);
- прямая центра масс с интервалом; P(кувыркание);
- поправка орбиты с ковариацией;
- поза по модам.

### 3.4 Калибровка — отдельная подсистема, а не тесты на 8 объектах
- **Независимый рендер истины**: трассировка лучей (Mitsuba 3, CUDA) — не та модель, что в выводе. Нужны
  BRDF материалов, свет Земли, самозатенение, тонкая геометрия.
- На каждую геометрию пролёта: сотни подстановок, движение из априорного распределения мусора (0–100 °/с,
  оси по сфере, кувыркание), плюс нулевые.
- Измеряется:
  - покрытие интервалов: 68 % должны накрывать истину в ~68 % случаев;
  - доля ложных «вращается»;
  - доля неверных направлений;
  - смещение скорости.
- Пороги решений берутся отсюда автоматически (заданная доля ложных), а не руками.

### 3.5 Обнаружение на GPU
GLRT заслонения по сетке (событие × сдвиг × dM × спектр) и нуль-прогоны — пакетные свёртки и регрессии. Выход —
кандидат с p-значением по калиброванному на нулях распределению. Затем тот же вывод (§3.3) уточняет орбиту
совместно с позой: отдельный Гаусс–Ньютон по «пикам полос» с отбором выбросов больше не нужен.

## 4. GPU: что и как считается

| Компонент | Ядро | Размер пакета | Оценка |
|---|---|---|---|
| поворот пятен + проекция | батч-матрицы (B × M × 3) | B ≤ 6·10⁴ грубо, ≤ 4·10³ точно | память ~ B·M·12 байт |
| размещение пятен в пиксели | scatter-add (Triton) или растеризация nvdiffrast | B × полосы × ~600 пикс. | основное время |
| свёртка с ядром PSF | FFT по пакету | — | дёшево |
| НК яркостей (k ≤ 8) | пакетное решение нормальных уравнений + активные множества, или проекционный Ньютон | B | k³ на гипотезу |
| робастная невязка | редукция; накопление в **float64** | B | убирает шум разностных производных |
| уравнения Эйлера | РК4, шаг ≤ 0,02 с, пакет | B × шаги | дёшево |
| HMC | `torch.func` / JAX `vmap` + градиенты | 64–256 цепей | минуты на объект |

Выбор стека — PyTorch (CUDA) + Triton для размещения пятен; альтернатива JAX (`vmap`, `jit`, NumPyro для HMC).
Нынешний код на PyTorch, поэтому PyTorch дешевле: переносится 70 % ядра модели.

Пропускная способность (оценка, проверяется в Ф1):
- грубая модель: ~10⁷–10⁸ гипотез/с на A100/H100 (CPU: ~10³/с на ядро);
- полный вывод объекта, включая апостериорное и отложенные моменты: ~1–5 минут на GPU.

Архив (~100–150 тыс. обнаружений, `PLAN_archive.md`) — порядка недель на одной GPU, дни на 8.

## 5. План работ — этапы с приёмкой

Каждый этап принимается только по измерениям. Сроки не обещаются: этап закрыт, когда приёмка пройдена.

| Этап | Что | Приёмка (измеряется) |
|---|---|---|
| **Ф0. Эталоны** | Заморозить наборы: вращение (8 объектов × настоящий/0/60 °/с), освещённые подстановки (3), центр масс, ATLAS и CZ-6A (настоящие), обнаружение (23 Starlink + МКС + нули) | эталонные числа записаны (`results/spin_real/baseline*.json` + новые) |
| **Ф1. Observation + прямая модель на GPU** | Неизменяемые записи пролётов; прямая модель с освещением, опорами, орбитой, движением (Эйлер), центром масс | совпадение невязки с CPU-моделью при тех же параметрах (отн. 10⁻⁴); скорость ≥ 10⁶ гипотез/с грубо |
| **Ф2. Правдоподобие** | Пакетные точные НК, робастный шум, κ, float64-накопление | гессиан положительно определён в минимумах эталонов; σ по гессиану совпадает с σ профиля |
| **Ф3. Вывод** | Глобальный перебор → LM → моды → Лаплас; сравнение моделей; отложенные моменты пакетом | на эталонах не хуже текущего; на освещённых подстановках ошибка скорости < 5 %, оси со знаком < 10° там, где свет различает |
| **Ф4. Калибровка** | Независимый рендер (Mitsuba), генератор подстановок по геометриям, отчёт о покрытии | покрытие 68 %-интервалов 60–75 %; ложные «вращается» ≤ 1 %; неверное направление ≤ 1 % среди «определено» |
| **Ф5. HMC** | Итоговые интервалы выборкой | совпадение с Лапласом на одномодальных; правильные веса мод на двойниках |
| **Ф6. Обнаружение на GPU** | GLRT + нули пакетом; совместное уточнение орбиты | те же обнаружения на наборе Ф0, доля ложных на нулях ≤ текущей (0,37 %) |
| **Ф7. Без модели** | Примитивы/воксели для сломанных объектов | на подстановках формы восстанавливают площадь ±20 %, ось ±10° |
| **Ф8. Архив** | Equant-пересечения → обнаружение → вывод → карточки | пропускная способность, отчёты по калибровке на всём наборе |

Текущий CPU-код остаётся эталоном до Ф3. После Ф3 сравнение идёт против Ф3.

## 6. Разбиение между агентами (для реимплементации)

| Агент | Модуль | Зависит от |
|---|---|---|
| A | `Observation`: сборка из снимков (геометрия push-broom — перенос из `passgeom`, `scenegeom`) | — |
| B | `ForwardModel` (GPU): пятна, свет, Эйлер, центр масс, опоры, орбита | A |
| C | `Likelihood`: НК, робастный шум, κ | B |
| D | `Inference`: перебор, LM, моды, Лаплас, сравнение моделей, отложенные моменты | C |
| E | `Calibration`: Mitsuba-рендер, генератор подстановок, отчёты покрытия | B (интерфейс), независимый рендер |
| F | `Detection` на GPU | A |
| G | Регрессия и эталоны (Ф0), CI-проверка каждого изменения | все |

Интерфейсы между агентами — типизированные записи (`Observation`, `Hypothesis`, `Posterior`, `Result`).
Ни один модуль не пишет в данные другого.

## 7. Риски
- **Глобальный перебор по 10⁸–10⁹ гипотез** может упереться в память и время размещения пятен. Запасной путь —
  иерархический перебор (грубая сетка → уточнение вокруг лучших) с гарантией по константе Липшица невязки
  (как ветви и границы в `bnb.py`).
- **Свет**: на настоящих снимках модель освещения не проверена эталоном. Калибровка независимым рендером — только
  косвенная проверка. Прямой эталон — объект с известным вращением (Envisat, TOPEX — пока не на снимках).
- **Геометрия Sentinel-2 ограничивает определимость** (две пачки полос, 0,35–0,6 с у встречных объектов). Это
  предел данных, не вычислений: новая система должна выдавать его как широкое апостериорное, а не скрывать.
