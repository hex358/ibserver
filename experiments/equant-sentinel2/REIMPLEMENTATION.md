# Equant × Sentinel‑2: полное описание системы для реимплементации с чистого листа

Документ для команды агентов на машине с GPU и Equant. Описывает, **что** система делает, **как** (алгоритмы и
формулы), **какие числа проверены**, **на каких ошибках мы уже теряли время** и **как принимать работу**.
Текущая реализация (CPU, PyTorch, Python) — в `s2sat/` и `scripts/`; её можно читать как справку, но строить заново.

---

## 0. Принципы (обязательны, от пользователя)

1. **Массово и одинаково для всех объектов.** Никаких ручных подстроек под объект (выбор орбиты, порогов, окон).
   Любое исправление — общее правило конвейера.
2. **Выдавать то, что оператор хочет знать, но не знает**, — параметры по фото (и в сочетании с орбитой), а не то,
   что следует из известной 3D‑модели (масса = объём × плотность бесполезна; для сломанного/неизвестного объекта
   модели нет).
3. **Каждое изменение проверяется на всём наборе сразу** (регрессия, §9): принимается, только если ни один объект не
   стал хуже. Исправление по одному примеру уже трижды ломало другие пролёты.
4. **Перед дорогим запуском**: (а) это задача пользователя? (б) нет ли ошибок конфигурации — малый прогон, воронка
   фильтров, промежуточные числа? (в) время уходит на разработку, а не на ожидание?
5. Без «честных отрицательных результатов» вместо исправления: если подстановка показывает, что истина лучше
   найденного, — чинить поиск; если хуже — это предел данных, и пролёт помечается как неинформативный.
6. Общение с пользователем — по‑русски, коротко, сначала результат.

## 1. Что система делает

Находит на снимках Sentinel‑2 (S2A/B/C, 10–60 м) **искусственные объекты, пролетающие между спутником и Землёй**
(Starlink, МКС, ступени, мусор), и извлекает по пикселям:

| Выход | Для кого | Статус |
|---|---|---|
| Обнаружение объекта на снимке + положение в каждой полосе | каталог, проверка орбит | работает (Starlink, МКС) |
| Уточнённая орбита (вдоль/поперёк следа, десятки м) против CelesTrak (км) | сближения | работает |
| Поза (ориентация корпуса по всей SO(3), углы каждого крыла) | операторы, ADR | работает на сильных сигналах |
| Вращение: скорость, ось (до зеркального двойника), вердикт «вращается/нет» | мусор, ADR | работает при ≥ 4–6 полосах |
| Поправка центра масс, площади к Солнцу/потоку, A/m, масса неизвестного объекта | орбиты, мусор | частично |
| Фотореалистичные кадры, листы «снимок/модель/остаток» | показ | работает |

## 3. Конвейер

### 3.1 Пересечения (GPU: Equant)
Найти моменты, когда объект проходит **под** Sentinel (между ним и Землёй) внутри поля зрения (веер ±10,5°),
днём (Солнце над горизонтом ≥ 10–40° по задаче), над сушей/побережьем (S2 не снимает открытый океан).
- Сейчас: перебор `s2sat/crossings.py` (шаг 30 с + уточнение). На GPU — **Equant** (`hex358/cull`, ветка
  `decay-study`): орбиты рядами Фурье по SGP4 + полином торможения, тор фаз, отсев K1/K2/K3; 1M объектов за 24 с
  на RTX 3090.
- Орбита для пролёта — **по каждому снимку каталога TLE** (правило fit‑span): свежая орбита при пересчёте назад
  уводит объект на десятки км; брать пролёт, если объект мог быть в кадре хотя бы по одной орбите.
- Возраст орбиты: для манёвренных (Starlink) ≤ 5–6 сут; для **неманёвренных (ступени, мёртвые спутники, Хаббл)
  можно до 30 сут** с окном ±25 км по фазе.
- Отбор по снимкам: запрос каталога STAC **по точке и времени каждого пролёта** (±10 мин), не всего каталога за
  окно (для месяцев это тысячи запросов → отказы). Кэш — по ключу набора пролётов, не по датам.
- **Облачность не фильтровать**: объект выше облаков, облако — фон. Маскируются только края облаков (параллакс
  между полосами ~100–200 м) и насыщенные пиксели.

Воронка (замер): 4180 пересечений → 131 дневных (возраст ≤ 30 сут) → 39 со снимком (крупные объекты, 5 мес.).

### 3.2 Геометрия push‑broom: где объект в каждой полосе
Полосы S2 смотрят под разными углами α вдоль трассы (и разными для чётных/нечётных детекторов — порядок полос
обратный). Объект на высоте h изображается на земле в точке пересечения луча «Sentinel → объект» с эллипсоидом;
движущийся объект в каждой полосе снят в свой момент и в своём месте (км между полосами).
- Видимый трек: для времени t — точка на земле; α трека в осях Sentinel; **корень** α_трека = α_полосы(детектор, x, y)
  по сеткам MTD_TL → положение и момент каждой полосы (`s2meta.band_roots`).
- **3D‑углы (`alpha_3d`)**: азимут визирования в MTD_TL отсчитан от местного севера в каждом узле сетки; считать
  луч в локальной ENU узла и время пересечения ньютоном по GPS‑орбите Sentinel, α — в осях спутника. Убирает
  систематику ~1 км поперёк.
- Орбита Sentinel — **GPS из MTD_DS** (кубический Эрмит), не TLE.
- Якобиан J_b (м снимка на м смещения объекта; он же камера «объект → снимок», увеличение ×3–6).

### 3.3 Обнаружение
- Окна COG вокруг положений полос для всех гипотез фазы dM (ошибка орбиты вдоль следа) — окна вокруг каждого
  источника орбиты (σ ≈ 0,85 км: 17/17 эталонов ≤ 1,5 км от ближайшего источника), шаг по фазе по «усилению»
  (м снимка на км фазы).
- Фон: **loglocal** — каждая полоса предсказывается регрессией по полосам, далёким по времени съёмки (блок 100 м,
  окно 300 м), в логарифмах (тень рельефа — общий множитель); маска объекта из подгонки фона.
- Модель заслонения (GLRT): в полосе b отклик y_b = 1e4·f·(ρ_b − ρ_фона,b); спектры «серый» и «красный»;
  2 параметра (f, A).
- Совмещение полос: сдвиги согласованы геометрией (по dM), растяжение узора полос.
- **Порог**: 20 нуль‑прогонов со случайными сдвигами полос; детекция — счёт ≥ медиана нуля + 4 (ложная тревога
  ≤ 0,37 % на событие); тяжёлый хвост (max − med > 4) — max + 3.
- **Второй ярус у источника орбиты**: свой нуль в ±2σ вокруг каждого источника, p по Гумбелю × число источников,
  отсечка **p ≤ 8,93·10⁻⁴** откалибрована на 3980 нуль‑прогонах (0,37 %). Вернул 12 детекций (7 Starlink).
- Прогноз SNR по теории (площадь, увеличение, контраст) → диагноз: detected / too_faint / borderline / blind /
  MISSED (→ повтор с окном до ±60 км).
- Ускорение по схеме Equant (`scripts/bnb_proto.py`): ветви и границы по гипотезам — ×1500–4500 отсев.

### 3.4 Уточнение орбиты объекта
- Измеренные положения пятна в полосах → θ = (вдоль, поперёк, радиус) км: Гаусс–Ньютон с весами Хьюбера, априори
  поперёк 1,1 км, радиус 1,9 км; σ по МНК и джекнайфу.
- Результат: σ вдоль/поперёк **7–10 м**, разброс пятен вокруг геометрии ~24 м; CelesTrak − снимок (медиана):
  SupGP‑до 0,31 км вдоль, GP 1,25–3,7 км, поперёк ~0,19 км. Прогноз: поправка фазы по снимку 3,5 → 0,9–1,0 км на
  0–0,5 сут; дальше для Starlink доминируют манёвры.

### 3.5 Окна остатков для формы/позы
Для каждой полосы: окно ±600 м (родное разрешение) вокруг геометрического положения; r (снимок − фон), s (шум),
g (фон), J, момент. Опоры полос — **геометрия по точной орбите**, не яркие пики (пики расходились до 84 м).

### 3.6 Поза по пикселям (без законов ориентации)
Дифференцируемая модель снимка (`s2sat/diffmodel.py`, `diffpose.py`):
- Сетка модели дробится до треугольников < 0,8 σ ядра; каждый — пятно с проекцией площади a = |R S · q|
  (q = m₁×m₂ — строки J/1000); замкнутые части — вес ½ (силуэт = ½ Σ|проекций|), открытые пластины — 1.
- Пятна раскладываются билинейно на мелкую сетку, свёртка FFT с гауссовым ядром полосы (ФРТ + пиксель + смаз
  push‑broom), выборка в центрах пикселей.
- Яркости групп материалов — **точные неотрицательные НК** (перебор активных множеств), невязка — псевдо‑Хьюбер.
  **Не** «НК, затем обрезать отрицательные» — модель становилась хуже пустой.
- **Яркости свои в каждой полосе** (спектр материалов не серый) — иначе вращение «изображает» спектр.
- Параметры: поворот корпуса R (тело → орбитальные оси, вся SO(3)), угол каждого привода крыла, сдвиг объекта (2),
  **сдвиги опор полос** (2 на полосу, априори 25 м).
- Глобальный поиск: **сначала сдвиг объекта** (сетка ±16 м × 100 поз; перебор и при найденном, и при нулевом) →
  сетка super‑Fibonacci по SO(3) (3000–4000) × приводы (шаг 60°) на **грубой модели** (окно по размаху объекта,
  сетка σ/1, **одна группа материалов**) → Adam (256 лучших) → L‑BFGS на точной модели → различные минимумы.
- Освещение (по выбору): Ламберт cos(n·s)⁺ стороны к камере + блик стекла (n·h)^60.
- Проверки: σ по Гессиану (разности), вероятности минимумов, отложенные полосы, подстановка.
- **Неоднозначности**: зеркальный двойник (ортогональная проекция, плоские части), 180° двойники симметричного тела.
- Результат: STARLINK‑30245 — невязка 7884 против 9601 «объекта нет»; поза по закону «на Землю» была хуже пустой
  модели (+1655). 32851 над морем — модель объясняет 86 % сигнала.

### 3.7 Вращение
R(t) = exp([ω]×(t − t₀))·R₀ в орбитальных осях, крылья постоянны. Решатель `solve_spin` (`diffpose.py`):
1. Позы подгрупп полос ≤ 0,2 с (поворот внутри мал) и групп (разрыв > 1 с).
2. Кандидаты ω из пар поз (ось и угол ΔR, **все целые k**: ω = n(θ + 2πk)/Δt) + «не вращается».
3. **Полный перебор ω при позах самой информативной группы**: ось 120 направлений × скорость 1–200 °/с шагом 2 °/с.
4. Градиент по всем параметрам (грубая → точная модель).
5. **Полный перебор поза × ось** (600 × 120) при найденной скорости и её целочисленных соседях |ω| + k·2π/Δt.
6. Зеркальный двойник: R′ = M R D_k, ω′ = −Mω (M = I − 2llᵀ) — выдаются обе оси, если снимок их не различает;
   различает освещение.
7. Решение «вращается»: выигрыш над лучшей статикой > κ·3·ln N **и** вращение предсказывает **отложенный момент
   съёмки** лучше статики: по очереди откладывается целая подгруппа ≤ 0,2 с, и вращение **ищется заново** по остальным
   (тот же решатель; позы подгрупп кэшируются — они от других полос не зависят). Дожим от решения по всем полосам
   недопустим (утечка: быстрая «скорость» держит позу каждой полосы в своей яме — 33558 и 33700 давали ложное
   «вращается» 399 и 1032 °/с). При < 3 моментах съёмки вращение (3 параметра = одна лишняя поза) не отличить от
   несовпадения полос → «не определяется». Подтверждение: сумма > 2κ·K и среди ИНФОРМАТИВНЫХ моментов (|d| > 2κ)
   лучше ≥ 2/3 — момент, не различающий модели, не голосует против (иначе при чужой модели отражения 32851
   отвергался: сумма +477 при пороге 26).
8. Самопроверка геометрии каждого пролёта: подстановка 0 °/с и 60 °/с на той же геометрии и шуме → если
   решатель путается, вердикт «геометрия пролёта не определяет вращение».

Проверено (подстановки, сила как у настоящего объекта):
| Пролёт | полосы/разброс | 60 °/с → | ось |
|---|---|---|---|
| 30245 | 10 / 2,7 с, 2 группы | 60,1 °/с | 1° |
| 30580 | 6 / 4,9 с, 2 группы | 59,9 °/с | 4° (до двойника) |
| 32851 | 6 / 1,4 с | 66,9 °/с | 2° (до двойника) |
| 3358, 33700, 32251 | 2–3 полосы, ≤ 0,36 с | не определяет | — |
Настоящие снимки работающих спутников (эталон: не вращается): 30245, 30580 — «не вращается» ✓.
**Направление — по свету** (отдельный шаг): скорость, ось и вердикт — от решателя без освещения (его проверка
отложенными моментами надёжнее: с моделью освещения в поиске отложенные моменты чаще уходят в ложное кратное), затем
найденное движение и его зеркальные двойники дожимаются моделью с освещением Солнцем; направление определено, если
двойник хуже > 2κ·3. Проверка физичной подстановкой — объект нарисован с освещением ДРУГОЙ моделью отражения
(cos^0,7, разброс по граням ±30 %, блик шире), 60 °/с:

### 3.8 Параметры для орбит и мусора
- **Центр масс по фото** (`DiffSpinCoM`): тело без внешних моментов вращается вокруг центра масс, орбита ведёт его же;
  p(t) = C·Rt·R·q − C·(Rt − I)·R·c — c свободен, видно только по повороту. По одному пролёту измеряется **прямая**
  в теле (ось вращения через центр масс): вдоль оси положение не измеряется в принципе (точки оси неподвижны).
  σ — по ПРОФИЛЮ невязки (c = ĉ ± 2 м, остальные параметры дожимаются заново); σ при закреплённых остальных была
  занижена в 2–3 раза, полный гессиан неположительно определён (плоские направления приводов). Подстановки 60 °/с,
  |c| = 0 и 3 м (30245, 32851): поперёк оси ошибка 0,06–0,54 м при σ 0,23–0,96 м (0,2–0,8σ); короткий пролёт
  (36341, 0,43 с) — σ ~11 м (не измеряется, так и выдаётся). Две прямые из разных пролётов
  (ось в теле меняется) → точка. Ось устойчивого вращения — главная ось инерции (наибольшего момента у мусора).
- **Тензор инерции по фото** (`DiffTumble`: уравнения Эйлера без внешних моментов, РК4; равномерное вращение —
  частный случай, совпадает до 0,001). Подстановки кувыркания (моменты оболочки модели 62:61:1, 60 °/с):
  30580 (полосы двумя пачками 0–0,3 с и 4,3–4,9 с) — кувыркание **обнаружено** (выигрыш 135 при пороге κ·5·ln N = 83),
  но отношения моментов не единственны (3,5:2:1 с той же невязкой, что истина); 30245, 32851 — отход от равномерного
  ниже порога. Причина — съёмка S2 двумя пачками полос: каждая даёт (R, ω), всего 12 условий на 11 параметров.
  По одному пролёту измеряется: изменение ω между пачками (вращение НЕ вокруг главной оси) или, при равномерном
  вращении, одна главная ось (ось вращения). Отношения моментов — по нескольким пролётам одного состояния.
- Поправка центра масс к измеренному положению (по позе и модели/форме) — вдоль/поперёк, время.
- Площадь сечения к Солнцу и к набегающему потоку в найденной позе (средняя за оборот при вращении).
- B = C_D·A/m; ȧ по ṅ из TLE (B = 12,741621·B*); срок жизни — интеграл по экспоненциальной атмосфере (Vallado).
- **Масса неизвестного объекта = измеренная площадь / (A/m из торможения орбиты)** — план, не сделано.
- Тензор инерции — из **измеренной** формы (тонкостенная оболочка), не из каталожной модели.
- Обломки рядом (пятна ≥ 5σ в ≥ 3 полосах на одном смещении), спектр материалов по 13 полосам.
- **Без модели** (сломанный объект): подгонка примитивов (цилиндр/пластина/бокс) — план.

### 3.9 Рендер (вторично)
Mitsuba, Солнце и свет Земли из того же снимка, материалы по классам; **фотометрическая проверка**: интегральный
контраст рендера против снимка в R/G/B → измеренная поправка яркости объекта.

## 5. GPU‑план

- **Пересечения**: Equant (CUDA) — каталог ~20–25 тыс. объектов × 3 Sentinel × 2015–2026: 5,7 млн пересечений,
  ≈ 535 тыс. в кадре без облаков, ожидаемо найденных 100–150 тыс. (`PLAN_archive.md`).
- **Чтение снимков**: AWS us‑west‑2 (S3→EC2 бесплатно), 10–20 ТБ чтения на весь архив; g6.12xlarge ~4,6 $/ч;
  этап 1 за 8–12 ч при параллельном чтении.
- **Обнаружение**: z‑карты, GLRT и нуль‑прогоны — пакетно на GPU (свёртки, регрессия фона по блокам).
- **Поза/вращение**: дифференцируемая модель — пакет B поз × полосы; сетки SO(3) × ось × скорость (~10⁵–10⁶ оценок
  на объект) — на GPU секунды. FFT‑свёртка по полосе, scatter‑add пятен.
- Equant для гипотез: ветви и границы по (dM, сдвиг) и по (R₀, ω) — та же схема отсева, что в K1/K2/K3.
